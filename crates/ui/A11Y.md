# Accessibility

egui on the web draws to a canvas, so the page has no accessibility tree of its own. Every frame the screen
describes itself as `twin::Node`s (plan rule 3) and `web.rs` reconciles them into a hidden DOM, `#controls`.
The canvas is `aria-hidden` and `tabindex=-1`; the twin is what keyboards and assistive technology use.

The same nodes feed the native window (see "Native window" below), so the Windows build has a tree of its own.

## What the twin exposes

| Part | Twin |
|---|---|
| Landmarks (`a11y::landmark`) | `banner` (header), `main` holding `region "Page image"` and `region "Transcript"`, `complementary "Word panel"` (tray), `dialog` + `aria-modal` while a dialog is open. Behind a dialog the banner, main and tray are `inert` and `aria-hidden`: no landmark, heading or Tab stop of the screen is reachable until it closes |
| Headings | one `h1` (the student, or the screen), `h2` for the page and the word panel, `h3` for empty states |
| Groups and lists (`a11y::group_of`) | `group "Layout"`, `"Which text to show"`, `"Zoom"`, `"Which pages"`, `"Theme"`; `list "Pages"`, `"Choices for this word"`, `"Students"` with `<li>` per item |
| Roles per control (`Reg::role`) | `button`; `textbox`; `checkbox` / `switch` (`aria-checked`); `listitem` (a button inside a list item). Toggles are buttons with `aria-pressed` |
| Transcript | on the web the transcript is real, visible DOM text (see "Transcript as DOM text" below), not an invisible twin of canvas text: one `<p class="tx">` per line; flagged words are buttons inline in their sentence; struck-through text (`~~probably~~`) is a `<del>`; math is `role=math` with `aria-label` from `a11y::tex_speech` and, inside it, KaTeX's MathML (its structure is in the accessibility tree: `MathMLFraction`, `MathMLSquareRoot`, for math navigation and Nemeth / UEB braille); the TeX source laid over it for find and copy is `aria-hidden`, so the formula is still one node and its TeX is not read. Spoken math keeps scope: "the sum from i equals 1 to n of x sub i", "x to the power of a plus b end of power plus c", "absolute value of x minus 3 end absolute value", "the fraction the fraction 1 over 2 end fraction over 3 end fraction" (an inner fraction is always closed; a short "1 over 2" only when nothing can attach to it, so a half followed by x is "the fraction 1 over 2 end fraction x"), "the 2 by 2 matrix, row 1: a, b; row 2: c, d; end matrix" (also determinants and cases), "n choose k" |
| Page | the page image is `role=img` "The scanned handwritten page" laid over the stage; the zoom button is named "Fit the page to the pane, zoom 100%"; the student's "2 pages, 96 words" line is a paragraph under the h1 |
| Live regions | `#announce` (polite) and `#announce-alert` (assertive) are always in the page; `Ctl::say` / `say_node` feed them: decisions, who the student is now, which page, the toast, "Saved.", a failed save. A decision also says where the panel moved on to ("Used the suggested word. Now on page 2 of 2. Next, word 2 of 4: a word that could not be read. Nothing is chosen for it yet."; the page is named only when it changed), so a second Enter is never blind; moving a page says "Moved to position 2 of 2." The toast is spoken only through the live region (it is not a paragraph of the transcript). Counts (`student-status`, `tray-count`) and the save state are plain paragraphs read in place, never live regions of their own (round 5: one decision used to write three of them). Errors (`*-error`) are `role=alert`. What belongs to one action is one utterance: the sentences of a frame are joined into one write, "Marked as checked." leads the next student's name (`Ctl::say_node_after`), and a second write within 300 ms is appended to the first instead of replacing it (a live region rewritten twice in a moment is usually read as the second write alone) |
| Focus | `focusin`/`focusout` on the twin drive the canvas focus ring; a control that disappears or is disabled by its own action hands focus on (new screen: its `h1`; same group: the control beside it, so "Zoom in" at 400% lands on "Fit the page"; else the neighbour in its region) and says "Zoom in is not available now." Chrome moves `activeElement` to the body only at its next focus fix-up, so the twin does not trust a disabled button that still reads as active; a dialog takes focus on its first control, keeps Tab inside it and returns focus to what opened it; Tab is never trapped by the canvas |
| Text boxes | `typed-word` holds what the canvas box holds. The twin follows when the screen clears the box (a decision used the typed word) even though the box has focus: `data-app-value` is the value the twin was last told, so a box the person is typing in is left alone and one the app changed is rewritten. A screen reader never reads a value that is not on screen |
| Title | `document.title` and the window title are "`<assignment>` \| viSHion" while an assignment is open and "viSHion" otherwise (js/main.js, WCAG 2.4.2) |
| Focus is on screen | the twin is `overflow: clip`, so the browser cannot scroll it: when a control takes focus the canvas scrolls its scroll area to it (`Ctl::flush_scroll`, applied at the end of the scroll area the control sits in), clear of the sticky word panel; a tall region (the transcript) needs its top on screen. The page stage ring is drawn inside its pane, and the transcript ring shows after Tab (`:focus-visible`) and hides after a mouse click |
| Geometry | every node is laid over the canvas at the rectangle it is drawn in, for touch exploration, magnifier tracking and the highlight of a screen reader: controls (`Reg::at/size`, at least 44 x 44) and, since round 6, headings, lines, counts, legend and notes (`twin::geo`, `Ctl::heading/status/text/end_para` take the drawn `Rect`). A paragraph is positioned and its inline controls are placed relative to it (`web::reconcile` carries the origin); landmarks, groups and lists take the union of what they hold (`web::contain`, `tree::bounds`). Natively the same rectangles are the `BoundingRectangle` of Text nodes; the runs of a line share the line's. `#controls` has `pointer-events: none` and `overflow: clip` |
| Preferences | `prefers-reduced-motion` sets egui `animation_time = 0`; `prefers-contrast: more` selects `LIGHT_HC` / `DARK_HC`; `forced-colors` draws the canvas in the user's own system colours (`web::forced_tokens`: `Canvas` for every surface, `CanvasText` for ink and rules, `GrayText`, `LinkText`). Read once at start (`#controls[data-reduced-motion]`, `[data-high-contrast]`) |
| Zoom | the layout is in CSS pixels: 200% is a 640 wide viewport, 400% is 320. The page tools wrap below 354 points rather than run off the edge. In a window under 300 points high (400% on a laptop) the header is the top of the page and scrolls with it, the word panel stays in the page, and the panes stack. `web::fit_scale` keeps an egui point equal to a CSS pixel even when a browser sizes the canvas backing store differently from `devicePixelRatio`; `web::place` scales the twin if they still differ |

## Native window

`eframe` has the `accesskit` feature, but egui only gives AccessKit an unnamed node per widget (the Windows
tree used to be 50 `ControlType.Custom` nodes with no name). `ui::tree::of` turns the same twin nodes into a
platform tree as plain data (banner, `main` with "Page image" and "Transcript", "Word panel", dialog; groups and
lists; headings with their level; paragraphs with flagged words as buttons inline; math named by its spoken
form with the TeX as its value; toggles with their state; the text box with its value), and `ui::native`
writes it into AccessKit each frame, only while a screen reader is attached. Rules that cost a crash to learn:

- a control keeps the egui widget's own node id, so `Action::Default` from Narrator or NVDA is a click on that
  widget, and focus follows egui's;
- every node egui made this frame must stay reachable from the root or AccessKit's consumer panics in the
  window thread: the ones the twin does not use go under a hidden container, and a widget's own child nodes
  (the text runs of a text box) are kept;
- the window title is the assignment (`ViewportCommand::Title`), and announcements are a polite live `Status`
  node whose name changes with each one.

Automated: `cargo test -p vishion-ui native` (names, roles, levels, a press from the tree, reading order, and
every update of a session accepted by `accesskit_consumer`), and on Windows with a release build:

```
cargo build --release -p vishion-app --bin vishion
powershell -File crates/app/native-a11y.ps1   # launches --demo, walks UI Automation, invokes "Zoom in", rectangles of text
powershell -NoProfile -STA -File crates/app/native-a11y-critic.ps1          # Tab order and names
powershell -NoProfile -STA -File crates/app/native-a11y-critic-choices.ps1 -Poll   # repeated Enter in the word panel, FocusedElement polled
```

macOS (VoiceOver) and Linux (Orca) take the same AccessKit tree and are not run here: do the manual pass below
with the native build too.

## Transcript as DOM text (web)

The transcript region is not painted by egui on the web: `review::dom_unit` describes each line to the twin (`Node::Para::flags`: bold, italic, code, margin lead-in, display math, the look of a flagged word) and `web::dom_para` makes a visible `<p class="tx">` of it inside a `.tx-clip` box that is the part of the screen the scroll area shows (less the toast and a tray riding over the page: `web::overlays`, a `clip-path` polygon with holes). Everything else in `#controls` stays invisible (`opacity: 0`, `user-select: none`; the rule leaves the ancestors of `.tx-clip` alone).

- the browser lays the text out (`index.html`: the JS app's faces and measure, 22px/1.7 serif, 16px/1.5 sans for a margin note, `.w` chips); egui allocates the height the page *measured* (`web::measure`, one `ResizeObserver` per line), so everything under the transcript moves with it. A user stylesheet (text spacing, WCAG 1.4.12), a minimum font size, zoom and a font arriving all reflow it and the screen follows within a frame or two. The first frame of a line uses an estimate (`review::dom_estimate`);
- formulas are KaTeX's MathML (`katex.min.js` is fetched the first time a formula is on the page, the same way as the math font); until it arrives the TeX is shown in monospace;
- a flagged word is a `<button class="w">` whose accessible name is the same sentence as before (`Spelling to check: confidance. Show options.`) and whose text is the word. Its box is 44 high (8px of padding taken back by a negative margin; the painted word is the JS app's 4px of padding round the text); its focus ring is still drawn by egui, at the rectangle the page measured (`Ctl::dom_chips`);
- a click on a word goes through the control layer (`act:word-...`), a click on the text underlines the line (`act:line-...`, unless text is selected), the wheel and a touch drag over the text are handed to the canvas (`web::forward_scroll`) so the page scrolls as before;
- find-in-page, selection and copy work on it. Native keeps drawing the transcript with egui (`Ctl::dom_text` is only true on wasm).

Round 1 of the DOM transcript (blind critic), all in `transcript-dom.mjs` / `transcript-dom-critic.mjs`:

- **Copy** (Ctrl+C, context menu): eframe's document `copy` listener swallowed every copy (`stop_propagation` + `preventDefault`, clipboard unchanged). The vendored listener (`crates/vendor/PATCHES.md`) now returns when the document selection starts or ends in `.tx-clip`, so the browser copies it. With nothing selected in the transcript the canvas still gets the event.
- **What a selection gives**: each line ends with an `aria-hidden` zero-height `.tx-nl` block holding a newline (the lines are separate, absolutely placed boxes, which Chrome joined with no break: "samples,about"). The typeset MathML is `user-select: none` and the formula's TeX (`$...$`, `$$...$$` for display) is the selectable, copied form of it, one line (it used to come out one symbol per line). (Round 2 replaced the hidden 1px TeX span: see below.)
- **Reflow at 320 CSS px (WCAG 1.4.10)**: a formula wider than its column becomes a box that scrolls sideways (`.tx-math[data-wide]`, `overflow-x: auto`, set by `web::measure` from the line's own overflow; display math always scrolls), is a tab stop while it scrolls (`tabindex=0`, name from its `aria-label`; `focusin` sends `reveal:<line>` so the canvas scrolls the line on screen), and a wheel or touch drag that is mostly sideways over it scrolls it instead of the page. A flagged word wider than the column breaks (`max-width: 100%`, `overflow-wrap: anywhere`) instead of being cut off.
- **Ctrl+wheel / pinch** is the browser's zoom (WCAG 1.4.4): `forward_scroll` and eframe's wheel listener leave `ctrl_key` events alone, over the text and over the rest of the canvas.
- **A word's 44px reach** on the last row of a line is inside its line's box (`p.tx:has(.w)` has `padding-bottom` for it, from `lh`); `web::measure` takes that room off, so the screen is spaced as before and the room lies over the next line. Words are `z-index: 1`, so the foot of a word is not taken by the next line.
- **Triple click** selects the line without underlining it: a click on a line is acted on 280 ms later, and only if no selection came of it (a single click still underlines).

Round 2 (blind critic), `transcript-dom.mjs` sections 9 to 13 / `transcript-dom-critic-2.mjs`:

- **Word panel over the transcript** (390 and 768 wide, a bottom sheet): the clip-path hole was the box of the controls in the tray, which stops short of the sheet's padding and top. The review screen now reports the whole sheet (`web::set_sheet`, the rectangle of the `tray-sticky` area) and `web::overlays` cuts that out, so no text shows and none takes the pointer through any of it.
- **Find-in-page scrolls the transcript**: the page cannot scroll (the canvas owns the position), so the browser had nothing to reveal a hit with. `.tx-clip` is now a scroller (`overflow: auto`, no scrollbar) that rests `TX_BIAS` (100000px) down so it can also scroll up; its lines sit at that offset. Anything that scrolls it (Chrome's find bar, focus, selection autoscroll, keyboard) is turned into `scrollby:<dy>` for the canvas and the box goes back to rest (`web::install_transcript`); the scroll a focus caused is not forwarded, the screen's own reveal handles it. `window.find` does not scroll nested boxes at all, so a `selectionchange` that ends outside the box (and is not a drag) sends the same `scrollby:`.
- **Drag-selection at the edge** scrolls by the same path (Chrome autoscrolls the box, which is a scroller).
- **A formula is found where it is, and spoken once**: the typeset MathML is `aria-hidden` and `user-select: none` (a selection reads its symbols one per line); over it lies `span.tx-hit`, the TeX as transparent text squeezed to the formula's width (`web::measure`), `aria-hidden`, selectable, before the MathML in the DOM so that `window.find` (which stops at a hit it cannot select) reads it first. A find hit on a number in a formula is a visible box on the formula. The TeX `<annotation>` is dropped. Copy (`web::install_transcript`) hands the clipboard the text of the selection with each formula as its TeX (`$...$`, `$$...$$`). Nothing under `role=math` is in the accessibility tree: a formula is spoken once, from its `aria-label`.
- **Paragraph spacing (WCAG 1.4.12)**: lines are placed by the screen, so margins did not push anything. `web::measure` adds the line's `margin-top` and `margin-bottom` to the height it reports, and the screen leaves that room (chips are offset by the top margin).

Round 4 (blind critic), `transcript-dom.mjs` sections 12, 14 / `transcript-dom-critic-4.mjs`:

- **Keys that scroll a pane**: with the `Transcript` group (or a flagged word) focused, PageDown, PageUp, Home, End and, on the group (not on a word, which Space presses), Space and Shift+Space scroll the transcript as they do the JS app's `#tx-pane`. The twin is `overflow: clip` and the canvas owns the position, so the keydown handler (`web::install`) asks for it with `scrollby:<dy>` (a page is 0.8 of the window; Home and End send a distance the scroll area clamps). A formula that scrolls sideways keeps its own keys.
- **Hover sync** (js `R.hoverSync`): the DOM text takes the pointer, so the canvas never saw it over a line. `mouseover` / `mouseout` on a line send `hover:<line id>` (`Ctl::hover_line`); `review::page_image` draws that line's box on the page in the accent colour (`.box.on`) unless marks are off. Native sets the same field from egui's pointer.
- **The rest of the transcript pane is DOM text**: the student's name (`h1`), the count line, the legend, the pill, the token stat and the hint (and, while a page is being read, the streamed text and its note) are `.txc` elements in `.tx-clip` boxes, not canvas paint with an invisible copy. The screen describes them as before (`Node::Heading` / `Text` / `Status`, so native and every test are unchanged) and says, per node, that the web draws it (`Ctl::chrome`: CSS class and the part of the screen it may be seen in, `web::set_chrome`); egui allocates the height the page measured (`review::dom_block`, `dom_h`) and paints nothing. A user stylesheet (text spacing, another typeface, a minimum size) reaches them, and what follows moves with them. Because controls sit between them (Change student, Corrected / Original, the word panel's group), a run of DOM text is one `.tx-clip` box named after its first node; the lines of the transcript are the box that has `p.tx` in it (`.tx-clip:has(p.tx)`). Each is followed by an `aria-hidden` newline so a selection keeps them apart.
- **The streamed transcript** (page status `transcribing`) is a node of the twin (`stream`, with `stream-note`) on both targets, and DOM text on the web.  (The Rust app never sets that status itself yet, so it shows for a project the JS app left mid-run; `app_tests::round4_streamed_text_is_dom_text_on_the_web` covers it.)
- **Math structure for assistive technology**: the typeset MathML is no longer `aria-hidden`. Chrome exposes `MathMLMath` with `MathMLFraction`, `MathMLSquareRoot`, `MathMLRow` under the `role=math` node; the name stays the spoken form. Only the TeX copy is hidden.
- **Label in name** (WCAG 2.5.3): a word that could not be read is named "Word that could not be read: [illegible]. Show options." (the shown text is in its name, so voice control "click illegible" works).
- **No error flash**: until KaTeX arrives (about a quarter of a second) the TeX source is shown in the muted colour, not the red of a formula that failed.
